# Сервис цен

Проект первого семестра, продвинутый уровень. HTTP-сервис на Go загружает `data.csv` из ZIP- или TAR-архива в PostgreSQL и выгружает таблицу обратно в ZIP. База `project-sem-1`, таблица `prices`, порт PostgreSQL — `5432`, порт API — `8080`.

## Требования

- Go 1.23 или новее;
- PostgreSQL с базой `project-sem-1` и пользователем `validator`;
- `bash`, `curl`, `zip`, `unzip`, `tar`, `psql` для тестов из шаблона;
- для удалённого развёртывания — Ubuntu-сервер с SSH и правом `sudo` без запроса пароля.

Пароль учебного пользователя PostgreSQL указан в задании Практикума. Адрес сервера и SSH-ключ в репозиторий не добавляются.

## Локальный запуск

Запустите PostgreSQL на `localhost:5432`, создайте пользователя и базу с параметрами из задания. Затем:

```bash
./scripts/prepare.sh
./scripts/run.sh
./scripts/tests.sh 2
```

`prepare.sh` загружает Go-зависимости, собирает сервер и создаёт таблицу. `run.sh` запускает сервер в фоне, дожидается `/healthz` и возвращает локальный URL. Лог и PID лежат в `.build/`. Для одной только сборки, без подключения к PostgreSQL, можно выполнить `SKIP_DB_INIT=1 ./scripts/prepare.sh`.

Настройки соединения задаются переменными `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_SSLMODE`. Если они не заданы, используются параметры учебной базы из задания.

## API

`POST /api/v0/prices?type=zip` принимает архив через поле формы `file` или прямо в теле запроса. `type=tar` выбирает TAR; если параметр опущен, используется ZIP. Внутри архива должен быть `data.csv` с колонками `id`, `name`, `category`, `price`, `create_date`. Тестовый файл `test_data.csv` тоже принимается: именно его создают проверки из шаблона. Порядок колонок не важен. Ответ содержит число добавленных строк, число категорий в базе и суммарную стоимость всех записей:

```json
{"total_items":3,"total_categories":3,"total_price":600.00}
```

`GET /api/v0/prices` возвращает ZIP-архив с файлом `data.csv`. Записи выгружаются в порядке добавления.

Пример загрузки:

```bash
curl -F 'file=@sample_data.zip' 'http://localhost:8080/api/v0/prices?type=zip'
```

## Развёртывание на учебной ВМ

Сначала подключитесь к ВМ по SSH вручную и проверьте отпечаток ключа сервера. После этого передайте в `run.sh` адрес, пользователя и путь к приватному ключу:

```bash
DEPLOY_HOST=192.0.2.10 \
DEPLOY_USER=student \
DEPLOY_SSH_KEY=/path/to/private_key \
./scripts/run.sh
```

Скрипт определяет архитектуру ВМ, собирает Linux-бинарник, передаёт его по SSH, ставит PostgreSQL при необходимости, создаёт учебную базу и запускает сервис через systemd. Последняя строка вывода — IP-адрес сервера. SSH-проверка ключа хоста не отключается. Скрипт не меняет настройки межсетевого экрана.

Автотесты в `.github/workflows/go_check.yaml` и `scripts/tests.sh` оставлены из шаблона без изменений. Для этого уровня следует проверять результат шага `Test Level 2`, а не только общий статус workflow.
